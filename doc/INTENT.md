# Pinte 제품 의도

## 사용자 문제

마우스만으로 Windows를 사용하며 작은 버튼·마커·핸들에 포인터를 정밀하게 맞추기 어렵다. 화면을 크게 확대하면 조작하기 쉬워지지만 Windows 기본 돋보기에서는 복귀 제어를 찾기 어려워 갇힌다.

2026-09-10 사용자 확인: **버튼을 누른 채 이동하는 드래그는 가능하다. 어려운 것은 정밀한 위치 맞춤이다.** 시력 문제나 드래그 불가능을 전제로 설계하지 않는다. 브라우저·Blender·이미지 편집·일반 데스크톱 작업에 공통으로 쓰는 도구다.

## 제품 목표

- **원본 영역 편집 창 + 독립 확대 렌즈 창.** 영역을 지정할 때만 편집 창을 표시한다. 확대 중 기본값은 완전 숨김이며, 설정으로 5초 또는 항상 얇은 윤곽선만 표시한다. 윤곽선은 클릭·포커스를 가로채지 않는다. 이전의 상시 편집 테두리 요구는 2026-09-12 정책으로 대체한다.
- 렌즈 창은 테두리 안의 화면을 실시간 확대하며 따로 이동·리사이즈할 수 있다. 렌즈의 화면 밖 배치는 보정하지 않고 유지하며, 렌즈 이동·크기 변경은 원본 테두리의 위치·크기와 캡처 영역을 바꾸지 않는다.
- 원하는 부분을 크게 보고 확대된 위치에서 평소처럼 클릭·드래그한다. 실제 대상의 변화가 확대 화면에 계속 보인다.
- 확대 시작·배율·위치 조절·종료 전 과정이 마우스만으로 가능하다.
- 영역을 정하는 단계와 확대 조작을 구분한다. `화면 영역 지정`으로 테두리를 맞추고 `이 영역 확대`를 누르면 지정한 위치 그대로 렌즈를 연다. 핵심 기능과 화면을 단순하게 유지하며 실제 사용 테스트는 사용자가 직접 한다.
- 확대 중 `영역 편집` → 이동·8방향 크기 조절 → `완료`로 원본을 다시 정한다. 편집·모달·손 도구·렌즈 리사이즈 동안 입력을 해제하고, 완료 뒤 새 화면과 물리 버튼 해제를 확인해 재개한다. 일시적인 캡처 실패는 입력을 멈춘 채 자동 재시도하고 새 프레임 뒤에만 재개한다. 명시적 중지·복귀·닫기·입력/해제 실패는 자동 재개하지 않는다.
- 일반/컴팩트는 같은 상단·하단 도구막대 설정을 사용한다. 컴팩트는 이미지 여백 0·도구막대 48 DIP·버튼 최소 44 DIP·최소 창 440×280 DIP다. 렌즈 외곽 8방향 리사이즈는 원본과 배율을 유지하며, 모서리·변의 넉넉한 hit area를 사용한다. `렌즈 숨김`은 복귀가 아니라 클릭 지점의 작은 `렌즈 다시 펼치기` 오버레이로 접고, 누르면 원래 렌즈 위치·배율을 다시 연다.
- 2026-09-10 후속 사용자 요구: 확대 창은 항상 조작 가능한 상태를 유지한다. 확대를 열면 바로 조작을 요청하고, 창·영역·배율 조절과 경계 이탈 뒤에는 버튼 해제·최신 화면을 확인해 자동 재개한다. 별도 시작 버튼을 반복해서 누르게 하지 않는다.
- 배율·조작 중지·원래 화면 제어는 렌즈의 같은 자리에 남고 콘텐츠와 함께 확대되거나 사라지지 않는다. 렌즈를 이동하면 제어부도 함께 이동한다. 드래그 중에도 마우스로 입력을 해제하고 복귀한다.
- 대상은 현재 보이는 화면의 물리 좌표다. 특정 앱 연결이나 플러그인이 필요하지 않다.
- A/B 직선 획, 집기/놓기, 미세 이동은 직접 조작을 돕는 선택 기능이다.

## 수락 기준

| ID | 확인할 결과 |
|---|---|
| AC1 정밀 조작 | 확대 목표를 클릭하고 곡선·왕복 드래그가 아래 앱에 연속 전달된다. A/B 한 획은 대체 근거가 아니다. |
| AC2 복귀 | 선택·보기·조작·드래그·오류 상태에서 키보드 없이 입력을 해제하고 복귀한다. 복귀 조작이 아래 앱에 클릭으로 전달되지 않는다. |
| AC3 위치·배율 | 원본 테두리 이동·크기 조절이 캡처에 반영되고, 렌즈 이동은 원본 영역을 바꾸지 않는다. 두 창 이동·배율·DPI 변화 뒤 화면과 클릭 위치가 맞는다. |
| AC4 입력 상태 | 확대를 열면 조작을 요청한다. 일시 정지 뒤에는 버튼 해제·최신 화면을 확인해 자동 재개한다. 일시적인 capture 실패는 release·재시도 후 새 프레임에서만 재개하며, 명시적 중지·복귀·닫기·입력 실패는 요청을 끄고 release로 끝난다. |
| AC5 범용성 | 일반 브라우저, Mixamo와 유사한 마커 배치, Blender, Windows 앱에서 같은 조작법으로 확인한다. 호환 범위는 실측한 표면으로 보고한다. |
| AC6 결과 | 캡처 실패·입력 거부·미지원 표면은 작동한 것처럼 보이지 않는다. API 수락과 대상 반응을 구분한다. |
| AC7 보조 기능 | A/B 표식·직선 계획을 보조 도구에서 명시적으로 선택한다. 실시간 조작과 암묵적으로 섞지 않는다. |
| AC8 표시 정책 | 기본 확대에서 원본 편집 chrome이 없다. 5초/항상은 별도 클릭 통과 윤곽선만 보이고 캡처 제외 실패 시 숨김과 오류를 유지한다. |
| AC9 컴팩트·크기 | 일반/컴팩트×상단/하단에 고정 복귀 제어가 있고 실제 렌즈 리사이즈·pan·혼합 DPI 뒤 좌표 오차가 1 원본 픽셀 이내다. |
| AC10 배치·숨김 | 렌즈는 사용자가 화면 밖에 둔 위치로 되돌아오지 않고, 숨김은 복귀 대신 접근 가능한 펼치기 아이콘으로 전환되며 클릭 시 같은 배치·배율을 복원한다. |

## 비목표

- 안구 추적기 전용 SDK, 앱별 브러시·레이어·색상·리깅 제어.
- 자유 경로 녹화·재생, 키보드/컨트롤러 매핑 편집기, 기존 도구의 통합 복제.
- 미검증 상태에서 모든 게임·보안 화면·관리자 앱 지원 약속이나 자동 권한 상승.

## 현재 상태와 계획

컴팩트·표시 정책 구현/검증 상태는 [이번 실행 기록](../notes/runs/2026-09-12-compact-lens-source-indicator.md)을 따른다. 테스트 실행과 실제 UI 확인은 사용자 담당이며 이번 기능은 `NEEDS_USER_UI_CHECK`다. [추가 수동 시나리오](compact-lens-validation.md)를 사용한다.

2026-09-12 **영역 지정 단계·드래그 유지 수정 USER_CONFIRMED_PASS**. 수정 실행본 안내 뒤 사용자가 “아주 잘됨”으로 확인했다. 반복 드래그 해제는 이번 사용자 확인 범위에서 해결로 기록한다. 같은 소스의 표준 빌드는 경고 0/오류 0이며 테스트 실행과 UI 조작은 사용자에게 맡겼다. 드래그 중 이중 포인터·앱별 호환·혼합 DPI·경계/오류별 복귀까지 별도로 확인된 것은 아니므로 M5 전체 완료로 확대하지 않는다. [최신 확인 기록](../notes/runs/2026-09-12-region-selection-drag-confirmed.md), [수동 검증 안내](manual-validation.md)를 따른다. 과거 실패는 [이전 인계](../notes/runs/2026-09-11-drag-blocked-handoff.md)에 보존한다.
