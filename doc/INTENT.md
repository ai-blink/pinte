# Magnifier 제품 의도

## 사용자 문제

마우스만으로 Windows를 사용하며 작은 버튼·마커·핸들에 포인터를 정밀하게 맞추기 어렵다. 화면을 크게 확대하면 조작하기 쉬워지지만 Windows 기본 돋보기에서는 복귀 제어를 찾기 어려워 갇힌다.

2026-09-10 사용자 확인: **버튼을 누른 채 이동하는 드래그는 가능하다. 어려운 것은 정밀한 위치 맞춤이다.** 시력 문제나 드래그 불가능을 전제로 설계하지 않는다. 브라우저·Blender·이미지 편집·일반 데스크톱 작업에 공통으로 쓰는 도구다.

## 제품 목표

- **사용자 확인 구조: 원본 테두리 창 + 독립 확대 렌즈 창.** 원본 화면 위에 테두리 창이 계속 남아 확대할 영역을 표시한다. 테두리를 이동·크기 조절하면 캡처 영역이 바뀐다.
- 렌즈 창은 테두리 안의 화면을 실시간 확대하며 따로 이동할 수 있다. 렌즈 이동은 원본 테두리의 위치·크기와 캡처 영역을 바꾸지 않는다.
- 원하는 부분을 크게 보고 확대된 위치에서 평소처럼 클릭·드래그한다. 실제 대상의 변화가 확대 화면에 계속 보인다.
- 확대 시작·배율·위치 조절·종료 전 과정이 마우스만으로 가능하다.
- 배율·조작 중지·원래 화면 제어는 렌즈의 같은 자리에 남고 콘텐츠와 함께 확대되거나 사라지지 않는다. 렌즈를 이동하면 제어부도 함께 이동한다. 드래그 중에도 마우스로 입력을 해제하고 복귀한다.
- 대상은 현재 보이는 화면의 물리 좌표다. 특정 앱 연결이나 플러그인이 필요하지 않다.
- A/B 직선 획, 집기/놓기, 미세 이동은 직접 조작을 돕는 선택 기능이다.

## 수락 기준

| ID | 확인할 결과 |
|---|---|
| AC1 정밀 조작 | 확대 목표를 클릭하고 곡선·왕복 드래그가 아래 앱에 연속 전달된다. A/B 한 획은 대체 근거가 아니다. |
| AC2 복귀 | 선택·보기·조작·드래그·오류 상태에서 키보드 없이 입력을 해제하고 복귀한다. 복귀 조작이 아래 앱에 클릭으로 전달되지 않는다. |
| AC3 위치·배율 | 원본 테두리 이동·크기 조절이 캡처에 반영되고, 렌즈 이동은 원본 영역을 바꾸지 않는다. 두 창 이동·배율·DPI 변화 뒤 화면과 클릭 위치가 맞는다. |
| AC4 입력 상태 | 시작은 입력 꺼짐, 확대창의 조작 시작으로 명시적으로 켠다. 복귀·취소·닫기·capture 손실·실패 시 release로 끝난다. |
| AC5 범용성 | 일반 브라우저, Mixamo와 유사한 마커 배치, Blender, Windows 앱에서 같은 조작법으로 확인한다. 호환 범위는 실측한 표면으로 보고한다. |
| AC6 결과 | 캡처 실패·입력 거부·미지원 표면은 작동한 것처럼 보이지 않는다. API 수락과 대상 반응을 구분한다. |
| AC7 보조 기능 | A/B 표식·직선 계획을 보조 도구에서 명시적으로 선택한다. 실시간 조작과 암묵적으로 섞지 않는다. |

## 비목표

- 안구 추적기 전용 SDK, 앱별 브러시·레이어·색상·리깅 제어.
- 자유 경로 녹화·재생, 키보드/컨트롤러 매핑 편집기, 기존 도구의 통합 복제.
- 미검증 상태에서 모든 게임·보안 화면·관리자 앱 지원 약속이나 자동 권한 상승.
