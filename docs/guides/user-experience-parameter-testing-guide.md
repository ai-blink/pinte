# 사용자 체감 파라미터 개발·테스트 표준

버전 1.0 · 2026-09-22 · 범용 제안 표준

다른 프로젝트에 복사해 쓰는 자기완결 표준이다. 특정 기술·외부 문서에 의존하지 않는다. 예시 수치는 검증된 권장값이 아니다.

## 1. 적용 원칙

사용자 체감이나 실제 환경에 적정값이 좌우되는 동작은 **첫 기능부터 조절·관찰·복원 가능하게** 만든다.

모든 상수 노출이나 프레임워크 선행은 불필요하다. 보안·권한·무결성 제약은 고정하고 시험 환경·중지 조건은 사용자와 합의한다.

## 2. 초기 개발에 넣는 순서

1. 과업·성공·실패·중지 조건을 정한다.
2. 체감·환경 의존값의 계약을 정의한다.
3. 정상 기능과 설정 주입·조절·기록을 함께 구현한다.
4. 기준값을 보존하고 비교한다. 미검증 값은 가정으로 표시한다.
5. 통과 조건을 회귀 시험에 남기고 기본값으로 승격한다.

## 3. 파라미터 후보

| 영역 | 예시 | 확인할 사용자 결과 |
|---|---|---|
| 입력 | 누름·해제·체류, 간격, 감도, 임계 거리 | 누락·오작동·피로 |
| 화면·동작 | 크기, 대비, 전환, 속도, 가속·보간 | 가독성·멀미·정밀도 |
| 오디오·촉각 | 음량, 페이드, 지연, 진동 세기·길이 | 인지·동기·불편 |
| 비동기·통신 | 디바운스, 타임아웃, 재시도, 버퍼 | 응답성·중복·복구 |
| 캡처·장치 | 주기, 신선도, 해상도, 품질·오차 | 끊김·정렬·자원 |
| AI·콘텐츠 | 생성값, 길이, 스트리밍, 응답 예산 | 품질·일관성·비용 |

일반·전문가·안전값을 구분하고 불필요한 항목은 제외한다.

## 4. 파라미터 계약

비해당은 이유를 남긴다.

- ID·표시명·소유 모듈·목적·타입·단위·좌표계.
- 기본값·근거·범위·간격, 0/음수/누락 의미, 값 사이 제약.
- 측정 시작/종료 이벤트, 최소/최대/목표 중 의미.
- 적용 시점: 즉시/다음 동작/유휴/다음 세션/재시작.
- 관찰 지표·위험·중지 조건·복원값·노출 범위.

정의 예시:

```json
{
  "id":"input.arrivalDelay", "label":"도착 후 누르기 대기",
  "owner":"input-sequencer", "type":"integer", "unit":"ms",
  "default":100, "defaultEvidence":"unverified",
  "min":0, "max":1000, "step":10, "zero":"no-added-wait",
  "missing":"schema-default", "invalid":"reject", "meaning":"minimum",
  "events":["sourceMoveCompleted","pressIssued"], "applyAt":"idle",
  "exposure":"developer", "observe":"elapsed-and-user-result",
  "stopIf":"position-changed-or-release-failed", "restore":"lastApplied"
}
```

범위는 안전 한계 이내다. 타이머·프레임보다 세밀한 실행을 보장하지 않는다. 누락 기본값까지 확장해 기록한다.

## 5. 구현·환경 분리

조절 UI → 검증 → 실행 소유자 → 제품 엔진 → 기록. 별도 실행 경로는 만들지 않는다.

같은 코드의 개발 모드를 기본으로 한다. 별도 실행본도 엔진은 공유한다. 설정·로그·계정·데이터를 격리하고 실행본·프로필을 표시한다. 파일 복사만으로 격리되지 않는다.

독점 자원은 한 주체만 소유하며 테스트용으로 잠금을 풀지 않는다. 수신·모의 앱은 실환경 시험의 대체물이 아니다. 정식 데이터·외부 효과 시험은 별도 승인한다.

## 6. 적용·중지·복원 계약

`편집본 → 검증 → 적용 대기 → 실행 경계에서 전체 교체 → 적용 확인`

- 편집값과 적용값을 분리하고 실행 소유자 확인 후 revision을 표시한다. 묶음의 공통 적용 경계가 없으면 분리 적용을 명시한다.
- 동작·프레임·오디오 블록 등 원자 단위를 정하고 단위 안에서는 불변 스냅샷을 쓴다.
- 즉시=다음 안전 경계, 다음 동작=이후 접수부터다. 기존 큐는 revision을 유지한다. 유휴 적용만 접수를 막고 큐 종료를 기다린다. 세션/재시작은 해당 시작 때 확인한다.
- 적용 대기 한도 초과 시 요청을 취소하고 기존값을 유지한다. 안전하면 접수를 재개하고 불확실하면 중지한다. 강제 적용은 금지한다.
- 취소하면 미실행 항목을 버리고 진행 중 동작은 안전 종료한다. 해제·정지·정리 실패를 알리고 자동 재개하지 않는다.
- 즉시 미리보기는 가역 효과에 한정한다. 슬라이더마다 외부 효과를 발생시키지 않는다.
- 기본값·직전값·저장값·검증값을 구분한다. 복원도 적용 경계를 따른다. 설정 복원은 이미 실행한 입력·결제를 되돌리지 않는다.
- 프로필에 schemaVersion·revision·전체 값을 저장한다. 부분 쓰기를 막고 실패 시 기존 파일을 보존한다. 미지원 필드·버전·오류는 알리고 명시적 변환 또는 불러오기 거부로 처리한다.

## 7. 사용자 조절 패널

값·단위·의미·적용값을 묶는다. 숫자·슬라이더·증감 버튼은 사용자의 입력 수단과 정밀도에 맞춘다.

필수: 적용·상태·복원·프리셋·A/B·결과. 고급값은 접고 위험은 표시한다. 중지·복원은 항상 접근 가능해야 한다.

편집과 측정을 구분하고 포커스·캡처·부하 간섭을 통제한다. 필요할 때 별도 제어판을 쓴다.

## 8. 관측과 기록

요청값·실측값·사용자 결과를 분리한다. 간격은 단조 증가 시계, 날짜는 실행 구분용이다. 미동기 장치 시각을 빼지 않는다. API 완료는 대상 반응이 아니다.

runId·동작 ID에 빌드/모델·전체 설정·revision·환경·이벤트·큐 대기·실행 시간·오류를 연결한다. 관련 OS·장치·보조도구·배율·주사율·부하·망·캐시를 기록한다. seed만으로 재현을 보장하지 않는다.

관측 불가는 unknown, 사람 미확인은 NEEDS_USER_CHECK다. 원문·화면·토큰은 기본 수집하지 않는다. 로그 용량·보존을 제한하고 기록 비용·유실도 드러낸다.

## 9. 실험 절차

1. 과업·성공 기준·횟수·중지 조건과 기준 A·환경을 저장한다.
2. 한 항목을 바꾼 B를 적용한다. 예열·재시작·초기화 조건은 맞춘다.
3. A-B-A·순서 교대로 학습·피로·시간 영향을 확인한다. 성공/실패/취소/미확인을 구분한다.
4. 조합의 상호작용을 시험한다. 복수 변경 결과를 한 값의 효과로 단정하지 않는다.
5. 경계·연속·장시간·부하·다른 환경에서 재확인한다. 소수 성공은 안정성 보장이 아니다.

가상 기록 예시(시간은 일부 표본):

```text
run=R02 build=b17 profile=B@2 values={arrivalMs:150,holdMs:40}
task=같은대상누르기 env=E01(환경전체) order=A-B-A
attempts=10 success=8 failure=1 cancelled=0 unknown=1
requestedArrivalMs=150 observedArrivalMs=[151,168,153]
userFeel=반응은느리나누락감소 verdict=NEEDS_MORE_TEST
```

체감 척도 예: 1=과업 방해, 3=느리지만 가능, 5=지연 거의 없음. 대상 완료 신호가 없으면 성공은 사용자에게 확인한다.

## 10. 검증·완료 체크리스트

- [ ] 설계: 과업·성공·실패·중지 기준과 파라미터 계약.
- [ ] 단위: 범위·관계, 가짜 시계로 순서·취소·경계 검증.
- [ ] 통합: 저장·손상·버전 오류, 적용/복원, 큐·자원 소유권.
- [ ] 실환경: 제품 경로·입력 수단·관측 비용·실패 복구·A/B 반복.
- [ ] 사람: 과업 성공·체감·불편·접근성. 자동 테스트로 대체 불가.
- [ ] 출시: 실행본 식별·정식 설정 미오염·중지/복원·기본값 근거·지원/미확인 범위.

실패하면 기준값으로 복원하고 좌표·포커스·경쟁·외부 제약을 조사한다. 딜레이로 정확성 오류를 덮지 않는다. 개발용 변경 권한은 정식 배포와 구분한다.

금지: 수치마다 재빌드·무제한 재시도·안전 제한 해제.
