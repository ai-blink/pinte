# Pinte v0.3.0

**Released 2026-09-28**

Changes on `main` since [v0.2.0](https://github.com/ai-blink/pinte/releases/tag/v0.2.0).
English is canonical; a Korean summary follows.

## Highlights

- **In-app UI localization.** A new `Loc`/`{loc:Tr}` infrastructure (no
  `.resx`) backs a `Strings` dictionary covering all 9 windows: the entry
  window, the zoom lens, Settings, the region size/aspect ratio panel, the
  region-selection border, the advanced input-timing tuner, the collapsed-lens
  expand icon, and the source-region outline. Settings → Appearance now has a
  Language selector (System / 한국어 / English / 简体中文 / 日本語); switching
  applies immediately to every open window without a restart, the same way
  theme switching already worked. The choice is saved to
  `settings.json` and re-applied on launch, following the system locale by
  default.
- **Windows that stay open across a language switch update live.** The zoom
  lens, the region-selection border, and the input-timing tuner can remain
  open while Settings is used to change language (the tuner has no owner
  window and the border stays visible behind the modal Settings dialog), so
  each subscribes to the language change and re-renders its dynamic status
  text, toolbar labels, and accessibility names without recreating the
  window.
- **One pass of automated zh-Hans/ja review.** All 280 keys were reviewed
  against the Korean source by an LLM (glm-5.2) for awkward phrasing,
  mistranslations, register consistency, and UI-appropriate length; 46 of the
  findings were applied (e.g. a mismatched "pan tool" translation unified
  across 7 keys, two mistranslated "screen" labels, several accessibility
  names reshaped into noun phrases). This is a first automated pass, not a
  native-speaker review.
- **Settings window text now also reacts to language changes.** A bug found
  during this release — the "Current …" input-timing summary and the version
  line stayed in the previous language until the window was closed and
  reopened — is fixed; both now re-render immediately when the language
  changes while Settings is open.
- Two pre-existing WPF layout bugs surfaced while testing the language
  switch were fixed along the way: a `DockPanel` last-child ignoring its own
  `Dock` value (the nav sidebar tagline wrapped one character per line in
  English), and fixed-width combo boxes centering instead of left-aligning
  once their content column stopped being the widest.

## Verification

- `dotnet build Magnifier.slnx --nologo`: 0 warnings, 0 errors, across every
  slice of this work.
- Automated tests: Core 65 and Infrastructure 81 passed throughout. The App
  test suite still stalls on a pre-existing `SetSourceAsync` lens-test issue
  unrelated to this release; filtering to a single test class
  (`SettingsWindowTests`, `LensResizeTests`) also fails with an `Application`
  shutdown exception that reproduces identically on the pre-release commit,
  confirming it is a test-isolation artifact of running a filtered subset,
  not a regression.
- The Settings window's language switch was confirmed by the user in a
  Debug build (catching the two WPF layout bugs above and the "Current …"
  staleness bug fixed in this release).

## Known limitations

- Real UI language-switch behavior has not been checked window-by-window for
  8 of the 9 windows (only Settings has been eyeballed by the user).
- Chinese (Simplified) and Japanese strings have had one automated review
  pass, not a native-speaker review.
- Live target-application click/drag behavior across different Windows
  environments still needs ongoing validation, as in prior releases.
- Not code-signed. Secure desktops, elevated target applications, remote
  sessions and target-specific input policies can still block capture or
  input.

## 한국어 요약

v0.2.0 이후 `main`에 반영된 변경입니다.

### 주요 변경

- **앱 내 UI 다국어화**: 새 `Loc`/`{loc:Tr}` 인프라(.resx 대신 자체 `Strings`
  사전)가 9개 창(진입 창·확대 렌즈·설정·영역 크기/비율 패널·영역 지정 테두리·
  입력 타이밍 고급 조절 창·접힌 렌즈 펼치기 아이콘·원본 영역 윤곽선) 전체를
  덮습니다. 설정 → 화면에 언어 콤보(시스템/한국어/English/简体中文/日本語)가
  생겼고, 테마 전환과 같은 방식으로 재시작 없이 열려 있는 모든 창에 즉시
  반영됩니다. 선택값은 `settings.json`에 저장되어 다음 실행에도 적용되며,
  기본값은 시스템 언어를 따릅니다.
- **언어 전환 중에도 열려 있는 창은 즉시 갱신**: 확대 렌즈·영역 지정 테두리·
  입력 타이밍 조절 창은 설정에서 언어를 바꾸는 동안에도 계속 열려 있을 수
  있어(조절 창은 owner가 없는 독립 창, 테두리 창은 모달 설정 창 뒤에서도
  계속 보임) 각각 언어 변경을 구독해 동적 상태 텍스트·툴바 라벨·접근성
  이름을 창 재생성 없이 다시 그립니다.
- **zh-Hans/ja 자동 검수 1차**: 280개 키 전체를 한국어 원문과 대조해
  LLM(glm-5.2)이 어색한 표현·오역·존댓말 불일치·UI 문자열 길이를 검수했고,
  46건을 반영했습니다(예: 손 도구 오역이 7개 키에서 통일, 오역된 "화면"
  라벨 2건, 일부 접근성 이름을 명사구로 재정리). 원어민 검수가 아니라
  1차 자동 검수입니다.
- **설정 창 자체의 텍스트도 언어 전환에 반응하도록 수정**: 이번 릴리즈 준비
  중 발견한 버그 — "현재 …" 입력 타이밍 요약과 버전 표시가 창을 닫았다
  열기 전까지 이전 언어로 남아있던 문제 — 를 고쳐, 설정 창이 열려 있는
  동안 언어를 바꾸면 즉시 갱신됩니다.
- 언어 전환을 테스트하며 발견한 기존 WPF 레이아웃 버그 2건도 함께
  고쳤습니다: `DockPanel`의 마지막 자식이 자기 `Dock` 값을 무시하던 문제
  (영어에서 사이드바 태그라인이 한 글자씩 세로로 줄바꿈됨), 고정폭
  콤보박스가 내용 열이 더는 가장 넓지 않게 되자 왼쪽 정렬 대신 가운데
  정렬되던 문제.

### 검증

- 이번 작업의 모든 슬라이스에서 표준 build 경고 0·오류 0.
- 자동 테스트: Core 65·Infrastructure 81 계속 통과. App 테스트 스위트는
  이번 릴리즈와 무관한 기존 `SetSourceAsync` 렌즈 테스트 hang으로 여전히
  끝까지 못 돌리며, 단일 테스트 클래스만 필터링(`SettingsWindowTests`,
  `LensResizeTests`)해도 `Application` 종료 예외로 실패하는데 릴리즈 이전
  커밋에서도 동일하게 재현돼 회귀가 아니라 필터링된 부분집합 실행 자체의
  테스트 인프라 문제임을 확인했습니다.
- 설정 창의 언어 전환은 사용자가 Debug 빌드로 직접 확인했습니다(그 과정에서
  위 WPF 레이아웃 버그 2건과 이번에 고친 "현재 …" 고착 버그를 발견).

### 알려진 제한

- 9개 창 중 설정 창을 제외한 8개 창은 실제 화면에서 창별 언어 전환 확인을
  아직 거치지 않았습니다.
- 중국어(간체)·일본어 문자열은 자동 검수 1차만 거쳤고 원어민 검수는
  아직입니다.
- 실제 대상 앱에서의 클릭·드래그 동작은 이전 릴리즈와 마찬가지로 사용하는
  Windows 환경마다 계속 검증이 필요합니다.
- 코드 서명되지 않았습니다. 보안 화면, 관리자 권한 대상 앱, 원격 세션,
  앱별 입력 정책은 여전히 캡처나 입력을 막을 수 있습니다.
