# Pinte v0.3.1

**Released 2026-09-28**

Changes on `main` since [v0.3.0](https://github.com/ai-blink/pinte/releases/tag/v0.3.0).
English is canonical; a Korean summary follows.

## Highlights

- **Fixed: the lens jumped to a different screen position after collapsing
  and expanding it.** Collapsing the lens to the hide icon and clicking that
  icon to expand it again is documented to restore the exact same position,
  size, and zoom — but `ExpandCollapsedLensAsync` only called `Window.Show()`
  and relied on WPF to restore the window's on-screen position. WPF's own
  `Hide()`/`Show()` cycle can recompute `Left`/`Top` from a stale DPI context
  while the window has no monitor association, drifting it noticeably (size
  stayed correct; only position shifted). The fix reasserts the exact
  physical bounds recorded right before hiding, the same way every other
  lens placement in this app already works: a native `SetWindowPos` call via
  `_windows.PlaceWindow`, instead of trusting WPF's internal restore.
- **Also confirmed (D-033 follow-up): all 9 windows now have user-verified
  language switching.** The 8 windows other than Settings (MainWindow,
  SelectionPreviewWindow, QuickRegionSettingsWindow, SelectionOverlayWindow,
  PointerTimingWindow, LensCollapseOverlayWindow, SourceIndicatorWindow) were
  checked by hand on the v0.3.0 production build — language switching works
  in all of them. This closes the last open item from the v0.3.0
  localization work.

### Verification

- Standard build: 0 warnings, 0 errors. Core 65 / Infrastructure 81 tests
  pass.
- The position-restore fix was reproduced and confirmed against a Debug
  build: recorded native window bounds before hiding and after expanding
  showed identical size but a large position drift before the fix, and an
  exact match after it. The user then re-verified the fixed Debug build by
  hand.
- The App test suite still cannot run to completion due to the pre-existing,
  unrelated `SetSourceAsync` lens test hang (tracked separately, not part of
  this release).

### Known limitations

- Chinese (Simplified) and Japanese strings have only had one automated
  review pass; native-speaker review is still pending.
- Live target-application click/drag behavior still needs validation across
  the Windows environments you use, as with every previous release.
- Not code-signed. Secure Desktop screens, elevated-privilege target apps,
  remote sessions, and per-app input policies can still block capture or
  input.

## Pinte v0.3.1 (한국어 요약)

[v0.3.0](https://github.com/ai-blink/pinte/releases/tag/v0.3.0) 이후 `main`의
변경 사항입니다.

### 주요 변경

- **수정: 렌즈를 숨겼다가 펼치면 화면 위치가 바뀌던 버그.** 렌즈를 숨김
  아이콘으로 접었다가 그 아이콘을 눌러 다시 펼치면 위치·크기·배율을 그대로
  유지하도록 되어 있는데, `ExpandCollapsedLensAsync`가 `Window.Show()`만
  호출하고 화면 위치 복원은 WPF에 맡기고 있었습니다. WPF의 `Hide()`/
  `Show()` 순환은 창이 모니터에 연결되지 않은 동안 오래된 DPI 기준으로
  `Left`/`Top`을 다시 계산할 수 있어, 크기는 정확히 유지되지만 위치만
  눈에 띄게 어긋났습니다. 숨기기 직전에 기록해둔 실제 물리 좌표를, 이
  앱의 다른 모든 렌즈 배치가 이미 쓰는 방식과 동일하게 `_windows.
  PlaceWindow`(네이티브 `SetWindowPos`)로 다시 적용하도록 고쳐, WPF의
  내부 복원 대신 명시적으로 좌표를 고정합니다.
- **추가 확인(D-033 후속): 9개 창 전체 언어 전환 사용자 확인 완료.**
  SettingsWindow를 제외한 8개 창(MainWindow·SelectionPreviewWindow·
  QuickRegionSettingsWindow·SelectionOverlayWindow·PointerTimingWindow·
  LensCollapseOverlayWindow·SourceIndicatorWindow)을 v0.3.0 정본 실행
  파일에서 직접 확인한 결과 모두 정상 동작했습니다. v0.3.0 다국어화
  작업의 마지막 남은 확인 항목이 닫혔습니다.

### 검증

- 표준 build 경고 0·오류 0. Core 65·Infrastructure 81 테스트 통과.
- 위치 복원 수정은 Debug 빌드로 재현·확인했습니다 — 숨기기 직전과 펼친
  직후의 실제 창 좌표를 기록해 비교한 결과, 수정 전에는 크기는 같고
  위치만 크게 어긋났고 수정 후에는 정확히 일치했습니다. 이후 사용자가
  수정된 Debug 빌드로 직접 재확인했습니다.
- App 테스트 스위트는 이 릴리즈와 무관한 기존 `SetSourceAsync` 렌즈 테스트
  hang으로 여전히 끝까지 실행하지 못합니다(별도로 추적 중, 이번 릴리즈
  범위 아님).

### 알려진 제한

- 중국어(간체)·일본어 문자열은 자동 검수 1차만 거쳤고 원어민 검수는
  아직입니다.
- 실제 대상 앱에서의 클릭·드래그 동작은 이전 릴리즈와 마찬가지로 사용하는
  Windows 환경마다 계속 검증이 필요합니다.
- 코드 서명되지 않았습니다. 보안 화면, 관리자 권한 대상 앱, 원격 세션,
  앱별 입력 정책은 여전히 캡처나 입력을 막을 수 있습니다.
