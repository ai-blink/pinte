# Magnifier 기능·UI/UX 전면 개편안

개정: 2026-09-10 · 상태: **두 창 구조 사용자 확인 / 구현 후보 반영 / 실사용 검증 중단**

[제품 의도](../../doc/INTENT.md) · [1차 조사](../research/2026-09-10-magnifier-first-pass.md) · [기술·전달 계획](../plans/2026-09-08-magnifier-m5.md) · [배치 목업](2026-09-10_magnifier-redesign-interactive.html)

## 1. 한 줄 목표

마우스만 사용하는 사람이 원본 테두리 창으로 확대할 영역을 정하고, 독립적으로 이동하는 확대 렌즈 창에서 정밀하게 클릭·드래그하며 원래 화면에 복귀하는 Windows 앱.

## 2. 문제

- **정밀도**: 사용자 확인상 드래그는 가능하나 작은 목표에 맞추기 어렵다. 첨부 Mixamo 화면의 작은 마커·관절 위치가 대표 사례다.
- **갇힘**: 기본 돋보기처럼 화면 전체가 커지면 복귀 제어를 찾기 어렵다. Esc나 단축키만으로 취소하는 흐름은 해결책이 아니다.
- **개편 전 제품 불일치**: 일반 미리보기 클릭은 입력을 보내지 않고 A/B 실행만 남아 있었다. 영역 선택도 드래그·Esc 중심이었으며 배율과 마우스 복귀가 주 동선에 없었다.

## 3. 사용자 & 맥락

키보드 없이 일반·안구마우스로 작업한다. 기본은 직접 클릭·드래그이며 집기/놓기·머무르기를 강요하지 않는다. 브라우저·편집기·Blender를 표준 Windows 도구다운 화면으로 다룬다.

## 4. 사용자 여정

| 단계 | 하려는 일 | 경험 |
|---|---|---|
| 진입 | 작은 대상 발견 | 확대 버튼으로 원본 테두리 창과 렌즈 창 열기 |
| 위치 | 확대 대상 지정 | 실제 화면 위 테두리를 이동·크기 조절 |
| 핵심 | **크게 보며 정확히 조작** | 목표가 커지고 같은 손동작으로 미세 이동 |
| 배치 | 편한 곳에서 조작 | 렌즈만 별도로 이동, 원본 영역은 유지 |
| 종료 | **원래 화면으로 복귀** | 렌즈 제어부의 원래 화면 버튼 한 번 |

## 5. 핵심 흐름

1. 확대 → 원본 테두리 창과 확대 렌즈 창 표시. 시작은 실제 입력 꺼짐이다. 테두리는 선택 후에도 실제 원본 화면 위에 남는다.
2. 테두리의 이동 손잡이·크기 손잡이로 영역을 정한다. 내부 화면은 가리지 않고 선택된 영역이 렌즈에 실시간 반영된다.
3. 렌즈 제목부를 잡아 원하는 위치로 옮긴다. 원본 테두리는 그대로다. 배율은 렌즈의 −/+로 조절하며 테두리 위치를 자동 변경하지 않는다.
4. 조작 시작 → 렌즈 안에서 클릭·직접 드래그 → 대응하는 원본 위치에서 실제 변화. 입력 중 원본 영역과 배율은 고정한다.
5. 다른 곳을 확대하려면 입력을 해제한 뒤 원본 테두리를 옮긴다. 두 창의 이동·크기 조절 동작은 아래 앱에 전달하지 않는다.
6. 원래 화면 → 누름 해제 → 실제 입력 끄기 → 두 창 숨김 → 진입 버튼 복원. 확인 모달은 없다. 다시 열면 원본 영역·렌즈 배치를 복원하되 입력은 꺼짐이다.
7. 드래그 중 렌즈 콘텐츠의 정지 경계에 진입하면 마지막 유효 위치에서 release하고 보기로 전환한다. 경계를 향한 이동을 원본의 긴 획으로 보내지 않아야 한다. 버튼을 놓으면 정상 드래그가 끝난다.
8. 캡처 실패·capture 손실은 해제 후 복귀 제어를 남긴다. Esc는 추가 취소 수단이다.

중단은 현재 위치에서 누름을 해제하는 뜻이다. 아래 앱의 변경을 되돌리는 실행 취소와 같다고 표시하지 않는다. 경계 해제·복귀 제어의 실제 동작은 기술 검증 필수다.

## 6. 화면 / 출력 의도

**확인된 구조는 두 창이다.** oCam 같은 영역 테두리를 원본 위에 띄우고 확대 렌즈는 별도로 둔다. 이전 A/B/C 배치 추천을 대체한다.

| 창 | 사용자 조작 | 변하는 것 / 유지되는 것 |
|---|---|---|
| 원본 테두리 창 | 손잡이로 이동·크기 조절 | 캡처 영역 변경 / 렌즈 위치 유지 |
| 확대 렌즈 창 | 제목부로 독립 이동 | 렌즈 위치 변경 / 원본 영역 유지 |
| 렌즈 콘텐츠 | 확대된 지점 클릭·드래그 | 원본의 대응 위치 조작 / 창 배치 유지 |

테두리 안쪽이 실제 캡처 영역이며 테두리·손잡이는 포함하지 않는다. 두 창과 제어부가 캡처에 재귀적으로 나타나지 않아야 한다. 겹침에서도 표시·입력 비간섭을 검증하며 특정 앱 창에 고정하지 않는다.

| 화면 | 주 행동 / 주 출력 | 정보 순서 |
|---|---|---|
| 진입 버튼 | 확대 / 위치 안내 | 확대, 최근 위치, 설정 |
| 원본 테두리 | 영역 이동·크기 / 실제 캡처 범위 | 테두리, 이동·크기 손잡이; 내부는 원본 표시 |
| 확대 렌즈 | 직접 조작 / 실제 대상 변화 | 확대 이미지, 상태·중지·복귀, 배율 |
| 보조 도구 | 선택 동작 / 결과 | 필요한 도구만 펼침; A/B·카운트다운은 여기 |

렌즈 제어띠: 원래 화면 / 조작 시작·중지 / 배율 / 보조 도구. 렌즈와 함께 이동하되 확대되지 않는다. 실제 테두리로 위치를 파악하며 원본 개요는 선택 보조다.

목업은 테두리 이동·크기와 렌즈 독립 이동을 시연한다. 실제 Windows 조작의 증거는 아니다.

## 7. 우선순위

| 구분 | 내용 |
|---|---|
| **안 함** | 앱별 도구 제어: 범용 좌표 조작에 집중; 자유 경로 재생: 실시간 조작과 목적이 다름; 키보드·게임패드 편집기: new-alt와 중복 |
| Must | 상시 원본 테두리·이동·크기, 독립 이동 렌즈, 직접 클릭·연속 드래그, 배율·중지·복귀, 입력 해제·좌표 일치 |
| Should | 두 창 배치 기억·프리셋, 우클릭·더블클릭·스크롤 화면 버튼 |
| Could | 1px 이동, 선택형 흔들림 보정·속도 조절, 집기/놓기, A/B 직선 획, 선택형 머무르기 동작 |

정확도 확보 뒤 보조 동작을 추가한다. 지연을 늘리는 필터링과 실제 입력 허용은 자동 활성화하지 않는다.

## 8. 성공 지표

수치는 측정 전 제안값이다.

| 문제 / 의도 | 측정할 결과 |
|---|---|
| 정밀도 / AC1 | 같은 작은 목표 10회 클릭·드래그에서 원본 대비 빗맞춤·재시도 감소, 작업 시간 악화 여부도 측정 |
| 갇힘 / AC2 | 각 상태에서 마우스 복귀 10/10, 익숙해진 뒤 5초 이내; 키보드·도움 요청 0회 |
| 좌표 / AC3 | 테두리 이동·크기는 캡처에 반영, 렌즈 이동은 원본 영역 불변. 두 창 이동·배율·DPI별 변환 오차 원본 1px 이내 |
| 지속 조작 / AC1·4 | 곡선·왕복 획과 마커 이동 중 끊김·자기 창 클릭·누름 잔류 0회 |
| 반응 / AC5·6 | 브라우저·Blender·Windows 앱 반응 각각 확인; 갱신 30fps·반영 지연 100ms 이내 목표는 계측 후 판정 |

## 9. 검증 계획

Codex는 좌표·상태·release와 빌드/테스트를 검증한다. 사용자는 실제 입력 장치로 정확도·복귀 비용을 확인한다. 실제 UI 조작은 사용자 요청 범위에서 수행하고 포커스 충돌 시 멈춘다.

두 창 배치 검토 → 전달 실측 → 조작·복귀 검증 → 보조 도구 순서다. DPI·음수 좌표·겹침·합성 입력·캡처 실패도 확인한다.

- **Plan B**: 한 전달 구조가 실패하면 두 창 UX를 유지한 채 다른 입력 경로로 AC1·AC2를 검증한다.
- **Plan C**: 연속 조작과 마우스 복귀를 모두 증명하지 못하면 입력을 닫고 보기로 복귀한다. M5는 BLOCKED로 남기며 A/B 완료로 대체하지 않는다.
