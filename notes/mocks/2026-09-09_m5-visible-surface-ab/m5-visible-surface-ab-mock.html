보이는 화면에 A에서 B까지 한 번 전달

중간

아래 미리보기에서 A와 B를 누르면 같은 위치에 표식과 연결선이 남습니다. 이 목업은 실제 마우스를 보내지 않습니다.

검토할 요지 — 입력 대상을 고르지 않습니다. 선택한 화면 사각형 아래에 지금 보이는 앱이 A→B 획을 받습니다.
표시A: 시작점B: 끝점예정된 직선실제 입력 허용은 A/B 실행 버튼 옆에서만 바꿉니다.
브라우저 또는 Blender처럼 아래에 보이는 화면 · 창 이름으로 제한하지 않음
실제 실행 전: 아직 아래 화면에는 아무 입력도 보내지 않음
선택한 영역X 340 · Y 220 · 960 × 540실제 입력: 꺼짐
A
B
3초
A 지정 또는 B 지정 후 위 이미지에서 지점을 누르세요.

지금 할 일

1
A를 찍기시작할 곳을 고르고 이미지 안을 누릅니다.
2
B를 찍기끝낼 곳을 고르면 노란 연결선이 보입니다.
3
실제 입력 켜기선택한 화면으로 보낼지 이 자리에서 결정합니다.
4
한 번 실행대기 후 미리보기가 비켜서고 아래 화면이 받습니다.
Esc는 언제나 취소카운트다운 또는 진행 중 입력을 멈추고 마우스 버튼을 놓습니다.
🔧 개발 연결 메모
표식은 클릭 당시 정규화 좌표를 보관해 다시 그립니다. 실제 실행은 ScreenRegion의 물리 좌표로 단일 Down(A) → Move(B) → Up(B)을 보냅니다. 실행 직전 미리보기만 숨기며 대상 창 핸들은 찾지 않습니다.

실행 시에는 미리보기가 길을 비킨다

작음

A/B를 찍는 행위와 실제 입력 전달을 분리해, 미리보기 자신이 아래 화면의 클릭을 먹지 않게 합니다.

중요 — 브라우저, Blender, 다른 어떤 앱인지 판단하지 않습니다. 현재 선택 사각형의 전역 화면 좌표만 사용합니다.
1. A/B 지정이미지 클릭은 표식만 갱신
→
2. 직선 확인두 중심을 연결한 선을 표시
→
3. 실행 허용같은 조작 줄에서 상태 변경
→
4. 카운트다운Esc면 실제 입력 없이 취소
→
5. 잠시 숨김아래 보이는 화면으로 한 획 전달
표식은 클릭 지점과 같은 의미여야 합니다.

창 크기·확대 비율·빈 여백이 달라도, 표식은 사용자가 이미지에서 누른 상대 위치를 다시 사용합니다. 정수 화면 좌표를 되돌려 그려 표식이 밀리는 방식은 쓰지 않습니다.

입력은 한 번뿐이어야 합니다.

A/B 실행은 자유 경로 재생이나 다중 획이 아닙니다. 한 번의 시작·이동·해제로 끝나며 모든 취소 경로에서도 해제를 시도합니다.

🔧 개발 연결 메모
상태 전이는 Disabled → Ready → Countdown → Pressed → Ready입니다. 미리보기의 보임 상태와 실시간 캡처 타이머가 충돌하지 않는지 실제 실행본에서 검증합니다.

M5 완료 판단

검증

코드가 아니라, 새 실행본에서 관찰한 결과로만 완료를 기록합니다.

±1표식 중심과 이미지 클릭 지점 허용 오차
2곳브라우저와 Blender에서 같은 흐름 확인
1획실제 A→B는 한 번의 down·move·up
통과

A/B 표식과 연결선이 보이고, 미리보기와 겹친 선택 영역도 계속 갱신됩니다. 실제 실행 때 아래 화면에만 한 획이 나타나고 미리보기는 곧 돌아옵니다.

실패

표식이 클릭과 어긋남, 미리보기가 입력을 받음, 실제 전달이 보이지 않음, Esc 뒤 버튼이 눌린 채 남음 중 하나라도 관찰되면 원인을 분리해 App·Core·Infrastructure의 해당 차단 지점만 수정합니다.

하지 않음

대상 창 하나로 제한, 앱별 도구 제어, 권한 상승, 자유 경로 녹화·재생은 이번 구현에 넣지 않습니다.

🔧 개발 연결 메모
기준 명령은 dotnet build Magnifier.slnx --nologo와 dotnet test Magnifier.slnx --nologo입니다. 실행 중인 exe와 새 빌드 산출물을 혼동하지 않습니다.
