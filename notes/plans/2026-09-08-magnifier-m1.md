# M1 영역 선택·확대 미리보기 계획

## 1. 목표

무엇을 끝내야 하는가:
- `영역 선택` 버튼으로 반투명 Windows 오버레이를 열고, 사용자가 고른 사각 영역을 이동·크기 조절 가능한 확대 미리보기 창에 표시한다.

완료 기준:
- 오버레이에서 누르기·드래그·놓기로 사각형을 만들고 Esc로 취소할 수 있다.
- 선택 결과와 "화면 캡처 미연결" 상태가 미리보기 창에 표시되며, 창은 기본 창 동작으로 이동·크기 조절된다.
- `dotnet build Magnifier.slnx --nologo`가 경고와 오류 없이 통과하고, 실제 사용자 화면의 수동 확인 결과가 남는다.

## 2. 범위

이번에 할 것:
- `src/Magnifier.App`에 메인 제어창, 선택 오버레이, 미리보기 창을 구현한다.
- WPF 포인터 capture를 취소·창 닫기·capture 손실 때 해제한다.

이번에 하지 않을 것:
- 화면 픽셀 캡처, 원본 화면 좌표 변환, Win32 P/Invoke, 대상 앱 입력 전달, Core/Infrastructure 프로젝트 신설.

## 3. 접근

큰 단계:
1. 메인 창에 큰 `영역 선택` 진입점을 만든다.
2. 전 화면 반투명 오버레이에서 사각 선택과 Esc 취소를 처리한다.
3. 선택 영역의 표시용 좌표와 크기를 resizable 미리보기 창으로 전달한다.
4. 빌드하고 실제 창 동작을 수동 확인한다.

중요한 판단 기준:
- 실제 캡처가 없음을 UI에서 명시해 동작한 것처럼 보이지 않게 한다.
- 좌표 상태가 UI 간 전달만 필요하므로 이번에는 새 프로젝트나 추상화를 만들지 않는다.
- 상태 전이 다이어그램은 실제 입력 세션이 없으므로 이번 변경에는 추가하지 않는다.

## 4. 검증

통과해야 할 확인:
- `dotnet build Magnifier.slnx --nologo`
- 실제 창에서 영역 선택, Esc 취소, 미리보기 이동·크기 조절을 확인한다. 자동화할 수 없으면 `NEEDS_USER_UI_CHECK`로 기록한다.

## 5. 남는 리스크

주의할 점:
- 미리보기에는 실제 화면 이미지가 아니라 선택 사각형의 자리표시자와 수치만 표시된다.

후속으로 넘길 것:
- M2에서 화면 캡처와 원본 화면 좌표 계약을 Core/Infrastructure 경계로 도입한다.
- M3에서 입력 gate와 항상 실행되는 release 경로를 추가한다.

## 실행 규율

- Finish Line: 영역 선택 결과가 이동·크기 조절 가능한 미리보기 창에 표시되는 WPF 동작을 실제로 남긴다.
- Scope Limit: `src/Magnifier.App`과 현재 상태·계획 문서만 변경한다.
- Review Budget: 빌드 또는 수동 확인에서 발견된 M1 차단 문제만 최대 두 번 수정한다.
- Stop Rule: 수락 확인이 통과하면 구현을 종료하고, 캡처·입력·좌표 변환의 제안과 구현을 시작하지 않는다.
- Completion Impact: 안구마우스 사용자가 선택 후 조작할 확대창 흐름을 캡처·입력 위험 없이 처음으로 확인할 수 있다.
