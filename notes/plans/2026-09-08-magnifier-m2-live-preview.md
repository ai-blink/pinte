# M2.1 실시간 미리보기 계획

## 1. 목표

무엇을 끝내야 하는가:
- 선택한 화면 영역을 일정 주기로 다시 캡처해, 미리보기 창의 이미지가 실시간으로 변하게 한다.

완료 기준:
- 단일 백그라운드 캡처 작업만 실행되며, 이전 캡처가 끝나기 전에는 다음 갱신을 시작하지 않는다.
- 선택 영역을 바꾸거나 미리보기 창을 닫으면 갱신을 중단한다.
- 캡처 실패는 갱신을 멈추고 미리보기에 원인을 표시한다.

## 2. 범위

이번에 할 것:
- App에 10fps 이하의 `DispatcherTimer`와 겹침 방지 guard를 추가한다.
- GDI 캡처를 백그라운드에서 실행하고 완료된 프레임만 WPF UI에 적용한다.
- 기존 캡처 흐름도에 주기 갱신 루프를 표시한다.

이번에 하지 않을 것:
- 입력 전달, 사용자 클릭·드래그 전달, 연속 녹화·파일 저장, 프레임 인코딩, 대상 앱별 최적화.

## 3. 접근

큰 단계:
1. 현재 선택 영역·미리보기 수명과 갱신 상태를 MainWindow에서 소유한다.
2. 타이머 tick은 이전 캡처가 끝난 경우에만 백그라운드 캡처를 시작한다.
3. 캡처 성공·실패·창 닫기·새 선택에 맞춰 타이머와 상태 문구를 갱신한다.
4. build/test와 실제 화면 변화 확인으로 검증한다.

중요한 판단 기준:
- 새 Core·Infrastructure 추상화는 필요 없다. 이미 있는 `IScreenCapture` 계약을 재사용한다.
- UI 스레드는 WPF 이미지 적용만 수행한다.
- 실제 입력은 기본 비활성 상태로 유지한다.

## 4. 검증

통과해야 할 확인:
- `dotnet build Magnifier.slnx --nologo`
- `dotnet test Magnifier.slnx --nologo`
- 실제 창에서 선택 영역의 화면 변화가 미리보기에 반영되는지 확인한다. 자동화할 수 없으면 `NEEDS_USER_UI_CHECK`로 기록한다.

## 5. 남는 리스크

주의할 점:
- 넓은 선택 영역과 일부 보호된 표면에서는 갱신률이 낮아지거나 캡처가 실패할 수 있다.

후속으로 넘길 것:
- M3에서 이 프레임과 Core 좌표 환산 계약 위에 입력 gate·release 경로를 추가한다.

## 실행 규율

- Finish Line: 실제 선택 화면을 안전하게 주기 갱신하는 미리보기를 코드·검증으로 남긴다.
- Scope Limit: App의 캡처 갱신 수명, M2.1 계획·상태·기존 캡처 흐름도만 변경한다.
- Review Budget: build·test·수동 확인에서 발견된 M2.1 차단 문제만 최대 두 번 수정한다.
- Stop Rule: 수락 확인이 통과하면 입력 전달·프레임 저장·성능 튜닝을 시작하지 않는다.
- Completion Impact: 사용자가 확대창 안에서 원본 화면의 변화를 계속 볼 수 있어 다음 상호작용 단계의 피드백 기반이 생긴다.
