# M5 범용 정밀 돋보기 개편 계획

개정: 2026-09-10 · 상태: **두 창·입력 중계 후보 구현 / 실사용 수락 BLOCKED**

## 목표와 정본

실제 화면 위 원본 테두리 창을 이동·크기 조절해 영역을 정하고, 독립 이동 가능한 확대 렌즈 창에서 직접 클릭·연속 드래그한다. 렌즈 이동은 캡처 영역을 바꾸지 않는다. 마우스만으로 중지·복귀하며 A/B 한 획은 보조다.

요구는 [INTENT](../../doc/INTENT.md), 두 창 UX는 [개편안](../brainstorm/2026-09-10_magnifier-redesign_design.md), 출처는 [1차 탐색](../research/2026-09-10-magnifier-first-pass.md)를 따른다. 이 파일은 기술·전달 순서를 소유한다. 이전 A/B 흐름과 3가지 배치 추천은 대체하며 과거 결과는 [기존 인계](../runs/2026-09-09-m5-realtime-magnifier-handoff.md)에 보존한다.

## 확인된 현재 상태

- SelectionOverlayWindow는 상시 투명 원본 테두리와 8개 크기 손잡이, 마우스 복귀 버튼을 제공한다.
- SelectionPreviewWindow는 독립 제목 이동·배율·고정 제어·직접 입력 중계 후보를 연결한다. A/B는 접힌 보조 도구에서 별도로 사용한다.
- MainWindow는 33ms 비중첩 캡처 요청과 두 창의 물리 배치 저장을 소유한다. 타이머 설정은 실측 fps가 아니다.
- LensViewport/LensInputState는 원본과 렌즈의 좌표 독립·기본 off·물리 해제 대기를 관리한다. WindowsLivePointerRelay는 전용 hook·자기 태그 SendInput·layered 창 입력 통과와 release를 구현한다.
- 표준 build 경고·오류 0, Core 23개 통과. native 대상 Down 수신 뒤 외부 입력 감지로 프로브가 중단됐다. R0의 연속 전달·마우스 복귀는 NEEDS_USER_UI_CHECK이며 UI를 자동 재시도하지 않는다. [구현 기록](../runs/2026-09-10-two-window-implementation.md)을 따른다.

## 기술 후보와 선택 기준

| 후보 | 이점 | 제약 | 채택 조건 |
|---|---|---|---|
| Windows Magnification API + 입력 변환 | OS 확대·좌표 전달 기능 활용 | mouse 변환에도 UIAccess 필요; 서명·신뢰 설치 경로; 창형/전체형 차이 | 실제 장치 연속 조작·고정 복귀 제어 증명과 배포 조건 수용 |
| 자체 확대 표면 + 입력 중계 | 기존 WPF/Core 활용, 배치 자유도, 일반 권한 범위 실험 | 표시 포인터·OS 포인터 분리, 원본 이벤트 차단·재전달, 합성 입력 재진입, capture·포커스 | 직접 드래그와 마우스 복귀 실측 통과 |
| 클릭마다 창 숨김·입력 후 복귀 | 일회 클릭·A/B에서 기존 경로 활용 | 확대된 연속 조작 표면 상실 | 주력 제외, 일회성 보조에만 사용 |

추가 사용자 레퍼런스 [MagnifierApp 비교](../research/2026-09-10-magnifierapp-reference.md)를 참고해 **자체 확대 표면 + 입력 중계 후보를 구현했다. 실사용 채택은 R0 실측 전이다.** 창별 메시지 분기는 이식하지 않았다. UIAccess가 필요하면 서명·설치·권한 조건을 설계 선택으로 올리며 자동 도입하지 않는다. UIAccess와 단순 관리자 실행은 같은 설정이 아니다.

전체 화면 API는 창 제외 목록을 지원하지 않는다. 항상 위 속성으로 복귀띠를 고정할 수 있다고 가정하지 않는다. 캡처 제외도 입력 목적지를 바꾸지 않는다. 레퍼런스의 PT_MOUSE 합성 장치 호출은 공식 지원 타입과 다르고 HTTRANSPARENT는 다른 스레드 창의 통과를 보장하지 않으므로 범용 해법으로 채택하지 않는다.

## 반드시 닫을 입력·복귀 계약

1. 원본 테두리 안쪽의 ScreenRegion과 렌즈 창 위치를 독립 상태로 둔다. 테두리 이동·크기 변경만 캡처 영역을 갱신한다. 렌즈 이동은 렌더링 원점만 바꾸며 원본 영역은 불변이다. UI DIP와 물리 픽셀을 구분한다.
2. WPF capture를 유지하면서 아래 앱도 같은 버튼 스트림을 받는다고 가정하지 않는다. Down→연속 Move→Up의 각 수신자를 관찰한다.
3. 중계 후보는 자기 주입 이벤트의 표식을 검토한다. LLMHF_INJECTED 전체 차단은 타 보조입력을 제거할 수 있으므로 금지한다. 상대 이동·절대 포인터 갱신을 각각 검증한다.
4. 원본 테두리·손잡이·렌즈·제어부를 캡처에서 제외하고 재귀·겹침을 검증한다. 테두리 내부는 원본 표시를 가리지 않는다. 두 창의 이동·크기 조절 입력은 아래 앱에 보내지 않는다. 대상 HWND 고정·앱별 분기로 대체하지 않는다.
5. 드래그 중 배율·영역·배치를 고정한다. 제어띠 앞 정지 경계에 진입하면 마지막 유효 좌표에서 Up 후 보기 전환이다. 경계 이동·복귀 클릭을 아래 앱에 보내지 않는다. 물리 버튼을 놓기 전 재무장하지 않는다.
6. 복귀·닫기·capture 손실·입력 실패·화면 구성 변경은 release와 입력 꺼짐으로 끝난다. 캡처가 낡으면 새 Down을 막고 진행 입력을 정리한다.
7. SendInput 수락은 대상 반응 증거가 아니다. 반환값만으로 UIPI 원인을 단정하지 않는다. 실패 안내는 확인 사실과 가능한 원인을 구분한다.

## 소유 범위

| 경계 | 역할 |
|---|---|
| App | 상시 원본 테두리·이동/크기 손잡이, 독립 렌즈·중지/복귀 UI, 창 조작과 콘텐츠 hit-test 분리 |
| Core | 좌표 변환·상태 전이·session release·실제 입력 기본 꺼짐 |
| Infrastructure | 확대/캡처·Win32 입력, 포인터 관측·자기 이벤트 구분·OS 결과 |
| Tests | 변환·상태·취소 자동 검증. 실제 대상 반응은 별도 확인 |

범용 입력 프레임워크·새 플러그인 체계를 선행하지 않는다. new-alt의 중계·release는 읽기 참고이며 창 고정·매핑 구조를 그대로 옮기지 않는다.

## 검증과 인계

- delivery workspace: C:/ai/projects/magnifier, 브랜치 main.
- 표준 실행본: src/Magnifier.App/bin/Debug/net9.0-windows/Magnifier.App.exe. 실행 중이면 임의 종료하거나 별도 출력으로 대체하지 않는다.
