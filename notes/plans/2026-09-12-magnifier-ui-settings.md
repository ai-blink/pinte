# Magnifier UI·설정 구현 계획

- 날짜: 2026-09-12 · 상태: **목업 사용자 승인 / WPF 구현 미착수**
- 기준: main `dd0feb0`의 영역 지정·드래그 유지 수정.
- 목표: 간단한 핵심 화면. [제품 의도](../../doc/INTENT.md) AC1~AC4 유지.
- 화면 기준: [승인 목업](../mocks/2026-09-12_magnifier-ui/magnifier-ui-mocks.html), [결정 기록](../runs/2026-09-12-magnifier-ui-mocks.md).
- 작업공간: `C:/ai/projects/magnifier`. 실제 조작·테스트는 사용자 담당.

## 1. 구현 순서

| 순서 | 구현할 결과 | 완료 기준 |
|---|---|---|
| 1. 핵심 화면 | 공통 색상·아이콘·버튼, 시작·영역 지정·확대 화면 정리, 1번/3번 도구 배치 | 영역 지정 과정과 복귀가 명확하고 두 배치에서 같은 조작 사용 |
| 2. 크기·비율 | 슬라이더 버튼의 빠른 설정, 픽셀 프리셋·비율 고정·가로/세로 | 테두리를 조절하면 원본 영역과 확대 화면이 함께 갱신 |
| 3. 전체 설정 | 톱니바퀴, 왼쪽 메뉴 모달, 스타일·테마·시작값 저장 | 설정 전환·닫기·재실행 뒤 선택값과 조작 흐름 유지 |
| 4. 사용자 확인 | 표준 빌드와 수동 확인 안내, 사용자 결과에 따른 수정 | 아래 확인 항목을 사용자 확인 범위에서 통과 |

## 2. 확정 화면

- 흐름: 시작 → 영역 지정 → 테두리 이동·크기 조절 → 확대 → 클릭·드래그 → 복귀.
- 원본 테두리·독립 렌즈를 유지한다. 확대 중 원본을 바로 조절하고 재지정 버튼은 제거한다.
- 1번은 상단 도구막대, 3번은 하단 도구막대다. 앱 설정에서 전환하며 자동 숨김은 없다.
- 도구막대: 이동 손잡이, 배율 −/현재값/+, 크기·비율, 앱 설정, 복귀.
- 입력 시작·중지 토글을 기본 UI에서 제거한다. 확대하면 바로 조작한다. 오류 후에는 복귀→확대로 다시 시작하며 “조작 재개 버튼” 안내도 정리한다.
- 복귀는 아이콘+글자로 항상 표시한다. 버튼은 선 아이콘·툴팁·접근성 이름과 44 DIP 이상 누름 영역을 갖춘다.
- 긴 상태 안내를 줄인다. 실패 이유와 기존 A/B 보조 진입은 남긴다.
- .NET 9 WPF·투명 창을 유지하고 공통 XAML 리소스로 색상·여백·버튼을 묶는다. 외부 UI 프레임워크를 추가하지 않는다.

## 3. 크기·비율 빠른 설정

선택·확대 화면에서 슬라이더 아이콘으로 연다. 값 변경·바깥 클릭으로 자동 닫지 않는다.

| 항목 | 동작 |
|---|---|
| 원본 크기 | 물리 픽셀 기준. 렌즈 창 크기·확대 배율과 별개 |
| 16:9 프리셋 | 320×180, 640×360, 960×540, 1280×720, 1600×900, 1920×1080 |
| 4:3 / 정사각형 | 640×480, 800×600, 1024×768 / 480×480, 720×720, 1080×1080 |
| 비율 | 16:9, 4:3, 1:1. 선택하면 고정을 켜고 가로 길이를 기준으로 맞춤 |
| 가로·세로 | 폭·높이를 교환. 정사각형에서는 비활성 |
| 고정 토글 | 켜면 크기 조절에도 비율 유지. 끄면 자유 조절 |

- 프리셋은 크기·비율을 적용하고 고정 상태는 유지한다. 임의 크기는 “직접 조절”로 표시한다.
- 8개 손잡이에 적용한다. 모서리는 반대 모서리, 한쪽 변은 반대 변의 중심을 고정한다. 화면 경계·최소 크기에도 비율을 유지하며 픽셀 반올림 오차만 허용한다.
- 실제 화면 범위와 DPI로 계산한다. 맞지 않는 프리셋은 이유를 표시해 비활성화한다. 방향·비율 변경이 화면을 넘으면 비율을 유지해 줄이고 적용 크기를 표시한다.
- 목업의 화면 크기 상수를 이식하지 않는다. 기존 요청 배율 0.25~8배·화면 맞춤 계산을 유지하고 실제 배율을 표시한다.

## 4. 앱 전체 설정

각 창의 톱니바퀴로 연다. 왼쪽 메뉴·오른쪽 내용·아래 닫기 버튼을 둔다.

| 메뉴 | 이번에 구현 |
|---|---|
| 화면 | 1번 상단 / 3번 하단 배치, 시스템·밝게·어둡게 테마 |
| 영역·배율 | 이전 영역·배율 기억, 기본 원본 크기, 시작 배율 |
| 앱 정보 | 간단한 마우스 사용법, 실행본 버전, 기존 진단 로그 폴더 열기 |

- 즉시 반영한다. X·닫기·Esc는 설정창만 닫는다. 바깥 클릭은 닫지 않는다. 좁은 화면에서는 내용을 스크롤하며 닫기 버튼은 남긴다.
- 모달은 현재 보이는 앱 창에 연결하고 중복 생성하지 않는다. 숨겨진 Main의 소유 창이 함께 숨던 문제를 재발시키지 않는다.
- “이전 값 기억”은 기본 켜짐이다. 두 창 배치·배율·비율·방향·고정을 기억한다. 끄면 다음 진입에 기본 960×540·2배 또는 지정 시작값을 쓴다. 기억 중에는 시작값 입력을 비활성화한다.
- 빠른 설정은 현재 원본, 기본 시작값은 다음 진입에 적용한다.
- 기존 `%LocalAppData%/Magnifier/layout.json`은 배치 저장에 재사용한다. `settings.json`에는 스타일·테마·기억 여부·기본값을 저장한다. 이전 파일의 누락 필드는 기본값으로 읽는다.
- 입력 허용·누름 상태는 저장하지 않는다. 손상된 설정은 기본값으로 열고 저장 실패는 알린다. 목업 저장소는 이전하지 않는다.

## 5. 입력·좌표 연결

- 확대=조작 요청, 복귀·닫기·입력 실패=release 및 요청 취소 계약을 유지한다.
- 누름·해제 대기 중에는 크기·배치 변경과 설정 열기를 보류한다. 복귀는 가능해야 한다.
- 모달이 열린 동안 입력 전달·배치 조작을 보류한다. 자동 재개되는 기존 `PauseAsync` 한 번으로 끝내지 않고 표시 기간에 맞춘 최소 보류 조건을 연결한다.
- 빠른 패널 위 클릭도 원본으로 새지 않게 팝업 창과 입력 제외 범위를 연결한다.
- 닫을 때 원래 조작 요청이 살아 있고 버튼 해제·최신 화면이 확인되면 재개한다. 복귀·닫기·실패로 취소된 요청은 살리지 않는다.
- 배치·테마 전환 후 도구 높이·렌즈 좌표를 다시 계산하며 원본은 유지한다. UI는 Win32 입력·캡처를 직접 호출하지 않고 드래그 감시 조건도 유지한다.

## 6. 파일 범위

- App: `App.xaml`·공통 리소스, `MainWindow*`, `SelectionOverlayWindow*`, `SelectionPreviewWindow*`.
- 신규 App 파일: 설정 창·빠른 패널·설정 모델/저장. 기존 `LensLayoutStore`와 배치 호환.
- Core/Infrastructure: 필요한 영역 크기 계산, 설정 중 보류·입력 제외 연결.

## 7. 확인과 완료

Codex는 원본 작업공간에서 `dotnet build Magnifier.slnx --nologo`와 참조·설정 형식을 확인한다. 실행 앱을 임의 종료하거나 임시 출력으로 대체하지 않는다. 필요한 계산·저장 회귀 테스트만 작성·컴파일하며 테스트 실행과 UI 조작은 사용자에게 맡긴다.

1. 영역 지정→확대→복귀가 마우스만으로 되고 기존 클릭·곡선·왕복 드래그가 유지된다. (AC1·AC2)
2. 원본 조절은 확대에 즉시 반영되고 렌즈 이동은 원본을 바꾸지 않는다. (AC3)
3. 프리셋·비율 고정·8개 손잡이·세로 전환·화면 경계에서 크기와 비율이 맞는다. (AC3)
4. 설정창·빠른 패널을 조작할 때 원본에 클릭이 새지 않고, 닫은 뒤 다음 조작이 이어진다. (AC4)
5. 1번/3번·테마 전환 후 배율·클릭 위치·복귀가 맞고 버튼이 잘리지 않는다. (AC2·AC3)
6. 재실행 시 설정 복원·기본 시작값·기존 배치 파일 호환이 맞는다.

확인 전은 `NEEDS_USER_UI_CHECK`다. 이중 포인터·앱별 호환·혼합 DPI는 별도 확인 대상이다. UI 통과는 제품 전체 완료가 아니다. 완료 후 문서·사용자 결과를 갱신한다. 커밋·푸시는 별도 요청 시 수행한다.
