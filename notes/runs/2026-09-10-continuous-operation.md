## 바뀐 동작

기존 창 이동·영역 변경·경계 이탈은 모두 조작 허용을 취소했다. 조작 요청과 일시 정지를 분리해 다음과 같이 동작한다.

- 확대 열기: 최신 화면·물리 버튼 해제를 확인하면 바로 조작 가능. 진입 클릭이 대상에 전달되거나 누른 채 재무장되지 않는다.
- 창·영역·배율 변경: 입력을 잠시 정지하고 갱신된 배치와 프레임을 사용해 자동 재개한다. 아래 앱에 전달되지 않은 손잡이 누름은 해제 대기로 오인하지 않는다.
- 경계: 마지막 유효 원본 좌표에서 Up을 한 번 보내고 물리 버튼 해제를 기다린다. 이후 새 입력을 받을 준비만 하며 추가 Down·클릭을 만들지 않는다.
- 화면 갱신 지연·캡처 실패: Up을 보내고 최신 화면이 돌아올 때까지 기다린다. 이전 조작 요청이 있으면 복구 뒤 재개한다.
- 명시적 중지·Esc·복귀·닫기·대상 capture 손실·입력/해제 실패: 조작 요청을 취소한다. 프레임이나 배치가 바뀌어도 자동 재개하지 않는다.
- A/B: 직접 입력과 상호 배제한다. 닫을 때 열기 전 조작 요청을 재개하되, 중간에 중지·복귀했다면 재개하지 않는다.
- UI: 조작 요청 중 `조작 유지 중`, 직접 중지 뒤 `조작 재개`. 진입 창 안내와 배율 조절 가능 조건을 맞췄다.
- 복귀/중지 도중 대기하던 UI 시작 요청이 뒤늦게 실행되지 않도록 요청 순서와 창 표시 상태를 재확인한다.

- Infrastructure: hook이 관측한 버튼 상태·남은 해제 이벤트·현재 버튼 샘플링·최신 프레임을 모두 확인해 재개한다. Configure는 이전 프레임 freshness를 무효화한다. native 호출은 이 경계에 유지한다.
- App: Main 진입에서 조작 요청, 렌즈·원본 손잡이/배율/DPI/캡처 경로는 일시 정지, 직접 중지/복귀는 취소. UI 요청 취소 확인 추가.
