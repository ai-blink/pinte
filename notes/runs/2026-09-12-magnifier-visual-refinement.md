# Magnifier 목업 정렬 시각 정비

날짜: 2026-09-12 · 범위: delivery UI polish · 상태: **후속 피드백 반영·표준 build/test 통과 / 실제 시각 확인은 NEEDS_USER_UI_CHECK**

## 완료선

작동 중인 두 창·입력·좌표 계약을 바꾸지 않고, 승인 목업 `notes/mocks/2026-09-12_magnifier-ui/magnifier-ui-mocks.html`의 밝은 작업면·카드·파란 강조·컴팩트 도구막대 계층을 실제 WPF에 적용한다.

## 반영

- 공통 WPF 리소스를 60/30/10 색상 비율(중성 작업면·흰 패널·단일 파란 강조), 4px 계열 여백, 8/10/14px 반경의 `App.xaml` 토큰으로 정리했다. 밝음/어두움 테마도 같은 토큰 이름을 교체한다.
- 시작 창은 브랜드 마크, 짧은 흐름 안내, 하나의 명확한 `화면 영역 지정` CTA를 가진 카드로 바꿨다.
- 원본 테두리는 어두운 갈색 막대와 노란 띠 대신 흰 제어 스트립·파란 테두리·작은 흰 손잡이로 바꿨다. 큰 투명 hit area는 유지한다.
- 확대 렌즈는 흰 카드·얇은 테두리·그림자·중성 캔버스, 제목 이동부, 구분선이 있는 컴팩트 도구막대로 정리했다. 상단/하단 도구막대 설정과 텍스트 복귀는 유지한다.
- 빠른 크기 패널·전체 설정은 카드 표면, 선택 상태가 보이는 좌측 메뉴, 배치 미리보기 카드, 간결한 설명과 명확한 닫기 동작을 사용한다.
- 원본 테두리의 chrome을 가로 40→28 DIP, 세로 90→80 DIP로 줄였으므로 `SelectionOverlayWindow`의 물리 aperture 계산도 같은 값으로 조정했다. 렌즈 제목 높이는 52 DIP로 변경하고 화면 맞춤 계산도 동기화했다.

## 사용자 피드백 후속 반영

- 시작 창의 안내 문구가 CTA와 겹쳐 보인다는 화면 증거를 반영해, 흐름 카드를 제거하고 제목·짧은 설명·단일 CTA·상태를 세로로 분리했다. 버튼 뒤에 가려지는 라벨이 없도록 했다.
- `⌗`만 있던 크기 설정의 의미를 명시했다. 렌즈 도구막대는 `영역 크기`, 원본 테두리 제어막대는 `크기`로 표기하며 기존 설명·자동화 이름은 유지한다.
- 마우스만 쓰는 사용자가 잡기 쉽게 원본 테두리의 상·하·좌·우 hit strip을 14→28 DIP로 넓히고, 모서리 손잡이는 10×10/2 DIP→18×18/3 DIP로 키웠다. 테두리도 3 DIP로 두껍게 했다.
- hit area 확장으로 chrome이 가로 56 DIP, 세로 108 DIP가 되었으므로 같은 변경에서 aperture의 물리 좌표 계산을 동기화했다. 보이는 경계와 실제 캡처 영역이 어긋나지 않게 하는 필수 변경이다.

## 고정 렌즈·상태 정리

- 사용자 확인에 따라 배율 변경에서 렌즈 `Width`/`Height` 갱신을 제거했다. 렌즈의 외곽은 기존 배치 크기를 유지하고, 확대는 내부 이미지 크기만 바꾼 뒤 중앙 기준으로 clip한다.
- clip된 보이는 이미지와 같은 원본 crop을 relay viewport로 구성한다. 따라서 고정 렌즈 안의 직접 Down→Move→Up은 전체 원본 비율이 아니라 화면에 보이는 확대 영역의 물리 좌표로 전달된다.
- A/B 표식과 가상 포인터도 큰 중앙 정렬 이미지의 실제 좌표를 marker canvas 좌표로 변환했다.
- 정상 상태에서 계속 공간을 차지하던 렌즈 하단 상태 패널은 접었다. 안전 상태 값은 유지하지만, 캡처 실패는 기존 캔버스 안내로 표시한다.

## 닫기·확대 위치 탐색

- Windows 기본 테두리가 없는 두 창의 제목부 오른쪽에 `×`를 넣었다. 원본 테두리와 확대 렌즈 모두 `원래 화면`과 같은 안전 경로(입력 해제 → 두 창 숨김 → 진입 창 복원)를 호출한다.
- 렌즈 내부에 24 DIP 가로·세로 스크롤바를 추가했다. 마우스 휠, 스크롤바, 손 도구는 같은 content offset을 바꾸고 매 이동 후 relay의 보이는 source crop을 다시 구성한다.
- `✋ 이동`은 명시적인 모드다. 켜면 `SetInputSuspendedAsync(true)`로 실제 relay를 멈춰 렌즈 안의 Down→Move→Up이 화면 이동만 하게 한다. 끄면 새 프레임·물리 버튼 해제 뒤에만 직접 조작이 자동 재개된다.
- A/B 보조 도구나 설정을 열기 전에는 손 도구를 해제해 보조 클릭·모달이 이동으로 해석되지 않게 했다.

## 비범위

- 직접 입력 relay, capture exclusion, frame freshness, 저장 구조, A/B 보조 동작은 바꾸지 않았다.
- HTML mock은 배치·토큰 참고용이며, 실제 Windows 캡처·입력 성공 증거가 아니다.

## 사용자 시각 확인

다음은 자동 UI를 통과로 추정하지 않는다.

1. 밝게·어둡게 테마에서 텍스트와 버튼 대비가 충분한지
2. 작은 원본 영역에서 새 제어 스트립이 테두리 aperture를 가리지 않고, 8개 손잡이가 계속 잡기 쉬운지
3. 배율을 바꿔도 렌즈 외곽 크기가 유지되고, 내부 이미지만 중앙 기준으로 확대·clip되는지
4. 렌즈의 제목부 이동 뒤 원본 좌표·확대 좌표·직접 클릭/드래그가 기존과 같은지
5. 설정 모달과 빠른 패널의 아이콘 버튼·Esc·복귀가 마우스로 명확한지
6. 원본 테두리와 렌즈의 `×`가 모두 입력을 해제하고 진입 창으로 복귀하는지
7. `✋ 이동`에서 캔버스 드래그·휠·24 DIP 스크롤바로 잘린 위치를 볼 수 있고, 해제 뒤 직접 클릭/드래그가 올바른 대상에 전달되는지

## 다음 세션

표준 실행본으로 새 시작 창의 라벨, `영역 크기` 명칭, 넓어진 테두리/손잡이, 고정 렌즈의 crop 직접 조작과 손 도구/스크롤 탐색을 확인한다. 디자인 방향을 다시 바꾸거나 동작 검증 없이 목업과 동일하다고 선언하지 않는다. 사용자 요청으로 이번 delivery를 로컬 커밋하며 푸시는 하지 않는다.
