# 개발 결정

## Vision

- D-001: 이 도구는 범용 Windows 화면 오버레이다. 특정 페인팅 앱의 내부 API에 결합하지 않는다.

## Layer boundaries

- D-002: WPF UI와 Windows 입력·캡처 코드는 분리한다.
- D-007: M2의 선택 영역과 캡처 프레임은 물리 화면 픽셀을 기준으로 한다. App은 WPF `PointToScreen` 결과를 Core `ScreenRegion`으로 바꾸고, Infrastructure만 GDI 화면 복사를 수행한다.
- D-009 (이전 M5, D-015로 대체): 당시 미리보기·선택 오버레이의 항상 위를 제거하고 캡처 제외를 적용했다. 이 단계의 사용자 관찰은 과거 run 기록으로 보존한다.
- D-010: A/B의 실제 입력 좌표는 정수 화면 좌표로 유지하되, 표식은 클릭 당시의 정규화된 미리보기 좌표로 그린다. 둘을 분리해 확대·DPI·반올림으로 표식이 클릭 지점에서 어긋나는 것을 막고, 실제 입력 전 점선 직선 계획을 보인다.
- D-011: A→B의 전달 대상은 선택한 `ScreenRegion` 아래에 현재 보이는 화면이다. 브라우저와 Blender는 M5 호환성 검증 대상일 뿐, 창 핸들 탐색·한 창 제한·앱별 분기를 추가하지 않는다.
- D-012 (시작 정책은 D-020으로 대체): 활성화와 실행 제어는 동일한 미리보기 조작 줄에 둔다. 사용자가 기본 창을 찾아야 하는 숨은 gate를 만들지 않는다.
- D-013: A→B의 `SendInput` 직전에는 미리보기 창을 잠시 숨겨 자기 창이 전역 포인터를 받지 않게 하고, 완료·실패·취소 경로에서 즉시 다시 표시한다.
- D-014: A→B 한 획과 확대 미리보기의 지속 조작은 별도 기능이다. A/B 지정 외 미리보기 클릭이 숨은 실제 입력이 되지 않게 하고, 실시간 조작은 입력 capture·미리보기 겹침·전역 전달을 함께 해결하는 명시적 모드로 다시 설계한다.
- D-015 (2026-09-10, 표시 정책은 D-023으로 대체): 원본 편집창과 렌즈는 독립 Topmost 창이며 캡처에서 제외한다. 원본 영역 변경과 렌즈 위치 변경은 별도 상태다. 실제 겹침 호환성은 R0 검증 대상이다.
- D-016 (2026-09-10): 자체 논리 포인터·전용 hook·태그 SendInput을 입력 엔진 후보로 구현한다. UIAccess·대상 HWND 고정·앱별 분기는 도입하지 않는다. native Down 한 번을 연속 전달 성공으로 취급하지 않는다.
- D-017 (2026-09-10): 경계에서는 마지막 유효 위치에서 Up을 보낸 뒤 보기로 복귀한다. 물리 버튼 해제 전에는 재무장하지 않는다. 실패한 Up은 누름 상태를 보존해 재시도하고, 설정에 입력 허용을 저장하지 않는다.

## Executor policy

- D-018 (2026-09-10): hook 내 동기 주입에서 원본/중계 Down·Up 중복을 재현했다. hook은 억제 결과를 즉시 반환하고 주입·창 스타일 변경은 같은 전용 스레드의 FIFO 큐에서 수행한다. 분리/겹침 곡선·왕복과 경계 해제 프로브를 통과했다. 제품 수락과 구분한다.
- D-027 (2026-09-14, D-028로 대체): WH_MOUSE_LL 훅의 `LowLevelHooksTimeout` 조용한 제거를 50ms 감시로 잡아 재설치. 즉시 재설치는 오탐 폭주로 D-028이 자기검증으로 교체했다. relay 스레드 Highest·`hook-reinstall` 기록은 유지.
- D-028 (2026-09-15, D-029로 보완): D-027의 상시 주입 오탐·이중 인스턴스 훅 충돌·누름 중 재설치 회귀를 막기 위해 제품 경로 Mutex, 태그 프로브 자기검증, 진행 중 입력 보호를 도입했다.
- D-029 (2026-09-16): 재설치 예산은 프로세스 수명 누적이 아니라 60초 이상 복구 시도가 끊긴 경우에만 초기화한다. 확정 훅 소실에서 relay가 누름을 소유하면 물리 release를 기다린 뒤 합성 Up 한 번과 stop으로 release를 보장한다. `relay-path`는 세션 armed·렌즈 안 callback·명령 dequeue·대상 Down 시작/거절만 기록해 정상 move hot path를 기록하지 않는다. key-demo-osk가 항상 `CallNextHookEx`를 반환한다는 소스 관찰만으로 직접 원인을 확정하지 않는다.
- D-019 (2026-09-10): 두 보조 창에 진입 창 Owner를 지정하지 않는다. Main Hide가 확대 창까지 숨기지 않게 하며 Main이 반환·종료 이벤트로 수명을 관리한다.
- D-020 (2026-09-10 사용자 후속 요청, D-026으로 보완): 확대를 열면 조작을 요청하고 계속 유지한다. 창·영역·배율·경계·화면 갱신 일시 정지는 요청을 보존하되 Up과 물리 해제를 먼저 처리한다. 최신 화면 뒤 자동 재개는 새 Down을 만들지 않는다. 명시적 중지·복귀·닫기·입력 실패는 요청을 취소한다. D-003/D-008/D-017의 시작·경계 재시작 정책을 대체하며 release와 입력 상태 비저장은 유지한다.
- D-021 (2026-09-12): D-020의 확대 전 영역 지정 단계를 명시한다. 테두리 선택 중 입력은 꺼지고 `이 영역 확대`로 확정해야 렌즈와 입력을 연다. 확정한 원본 위치는 유지한다. capture의 같은 thread 내부 인계나 원본 전면 유지 중 0만으로 중지하지 않으며, 외부 이탈·원본 종료·조회/입력 실패의 해제는 유지한다. 사용자 “아주 잘됨” 확인.

- D-003 (시작 정책은 D-020으로 대체): Down·Move·Up은 단일 세션과 release 경로로 처리한다.
- D-008: M3의 `SendInput` P/Invoke는 Infrastructure만 소유한다. App gate는 기본 해제이고, Core 세션은 취소·capture 손실·gate 해제·오류에서 `LeftUp`을 시도한다. UIPI 거부 원인은 API 결과만으로 확정하지 않는다.

## Security and safety

- D-004: Windows의 입력 권한 경계를 자동 상승으로 우회하지 않는다. 현재 구현은 입력 실패를 표시하며, API 결과만으로 UIPI나 실제 대상 반응을 확정하지 않는다. 사전 대상 권한 판별 기능을 구현했다고 안내하지 않는다.

## Workflow

- D-005: 구현 전 사용자 UX 설계 승인과 빌드 계획 검증을 요구한다.
- D-022 (2026-09-12): 사용자 요청대로 단순한 핵심 기능·화면을 우선한다. 테스트와 실제 UI 조작은 사용자가 직접 하며, 사용자 확인 범위를 넘어 앱별 호환성·남은 수락 항목까지 완료로 확대하지 않는다.
- D-023 (2026-09-12): 확대 중 원본 편집창은 Hide한다. Hidden 기본, Brief 5초, Always를 별도 SourceIndicatorWindow의 얇은 클릭 통과 선으로 구현한다. 캡처 제외 실패는 숨김+오류이며 indicator HWND를 relay 스타일 복원 목록에 포함하지 않는다. 표시창 native 스타일은 IWindowEnvironment/Infrastructure 소유다.
- D-024 (2026-09-12): 일반·컴팩트는 기존 ToolbarPlacement 하나를 공유한다. 모드 변경·렌즈 외곽 리사이즈는 원본·배율·저장 Lens rect 의미를 유지한다. 편집/모달/손 도구/리사이즈 보류를 합산하고 release·새 프레임 전에 재개하지 않는다. 표시 정책·모양은 RememberLayout과 별개이며 입력·편집·타이머 상태는 저장하지 않는다.
- D-025 (2026-09-12 작업 한정, 종료): 당시 기존 dirty와 Pinte 브랜딩·미추적 계획서를 보존하고 커밋·스테이징·푸시·브랜치 생성을 하지 않았다. 이 제한은 main `83074e5` 및 `v0.1.0-beta.1` 공개 pre-release 완료로 종료됐다.
- D-026 (2026-09-13): `CaptureOnceAsync`의 일시적인 캡처 예외는 `StopAsync`가 아닌 `PauseAsync`로 release·중계 일시 정지만 수행한다. 요청은 보존하고 다음 타이머 tick에서 캡처를 재시도하며, 정상 프레임을 `UpdateCapture(frame, true)`로 받았을 때만 재개한다. 명시적 복귀·닫기와 입력/해제 실패는 이 요청을 취소한다.

## Infrastructure
