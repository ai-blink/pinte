# 사용자 피드백

- UI는 HTML이 아니라 .NET 9 WPF 기술스택으로 만든다.
- 돋보기는 특정 앱 전용이 아니라 범용 Windows 오버레이다.
- 수치 제어는 버튼을 누르고 있는 동안 계속 변해야 한다.
- A와 B 사이의 자동 동작은 자유 경로가 아닌 한 번의 직선 획이다.
- A→B 한 획은 확대된 화면을 계속 조작하는 실제 돋보기의 대체물이 아니다. 두 흐름을 같은 것으로 안내하거나 완료 처리하지 않는다.
- 실행 중인 빌드에 확인되지 않은 UI·동작을 사용자에게 있다고 안내하지 않는다.
- 사용자 실제 실행본은 Debug 출력이 아니라 publish 단일 파일 `C:\app\Magnifier.App.exe`다. 수정은 승인 뒤 이 파일을 교체해야 사용자에게 도달하며, 실행 중이면 종료 뒤 교체한다(2026-09-14).

## 재발 방지 패턴

- 2026-09-24 사용자 확인: 클릭·더블클릭·드래그 전달은 되므로 다음 우선순위는 전달 경로를 바꾸지 않고 지연·복귀 대기를 줄이는 것이다. 현재 후보는 Arrival100ms/MinimumHold35ms를 유지하고 PostRelease60ms/BetweenGestures0ms로 줄인다. 실제 게임 반응을 확인하기 전에는 기본값 승격·배포 완료로 기록하지 않는다.
- `LLMHF_INJECTED`는 자기 출력 식별자가 아니다. 전체 주입 입력 우회는 보조 장치 Down/Move/Up도 버린다. 자기 `InjectionTag`만 제외하며, 태그를 지운 뒤 좌표·순서·시간만으로 출처를 추정하지 않는다. 게임이 고유 태그를 차단한다는 이전 가설은 증거가 없어 철회했다(2026-09-22 Astra 리뷰·회귀 복구).
- 이 PC 커서는 전부 주입(injected) 입력이다(보조 장치). "커서 움직임 = 물리 입력"을 전제한 휴리스틱은 오탐한다 — 훅/입력 감시는 반드시 자기주입 프로브로 검증하고, 재현 못 한 버그에 즉시 재설치 같은 능동 조치를 넣지 말 것(D-027→D-028 폭주 회귀, 2026-09-15).
- 앱이 두 개 동시 실행되면 각자 전역 WH_MOUSE_LL 훅을 걸어 훅 체인을 서로 느리게 만들고 타임아웃·폭주를 유발한다. 전역 훅을 거는 앱은 단일 인스턴스가 기본이다(D-028).
