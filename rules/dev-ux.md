# UX 원칙

- 첫 행동은 `확대 시작`이다. 두 창이 열리고 최신 화면·버튼 해제 확인 뒤 바로 조작할 수 있다. 렌즈의 시작 버튼을 따로 누르게 하지 않는다.
- 첫 배치는 두 창의 제목부를 포함한 물리 크기로 작업 영역 아래쪽에 잡는다. 이후 `확대 시작`은 저장 배치를 복원하고, 진입 창의 `두 창 아래쪽에 배치`는 두 창을 다시 배치하고 조작을 요청한다.
- 원본 테두리의 이동·크기 손잡이만 캡처 영역을 바꾼다. 내부의 실제 화면을 가리지 않는다.
- 렌즈 제목을 옮겨도 원본 영역은 유지한다. 원본 영역 조절은 렌즈 위치를 자동 변경하지 않는다.
- 렌즈를 화면 밖으로 옮기거나 바깥쪽으로 늘려도 앱이 작업 영역 안으로 보정하지 않는다. 외곽 8방향은 평소에도 넉넉한 모서리·변 hit area로 실시간 리사이즈하되, 이동 손잡이와 겹치는 상단 모서리는 작은 hit area로 두어 `SizeAll` 커서를 우선한다.
- `렌즈 숨김`은 원래 화면으로 복귀하거나 주 창을 여는 동작이 아니다. 누른 자리의 작은 `⌕` 오버레이로 접고, 그 아이콘을 누르면 기존 렌즈 위치·크기·배율로 다시 펼친다.
- 조작 상태·중지·원래 화면·배율은 렌즈와 함께 이동하며 콘텐츠처럼 확대되지 않는다. `조작 유지 중`은 현재 요청을 표시하고, 직접 중지한 뒤에는 `조작 재개`로 바뀐다.
- 직접 클릭·연속 드래그가 주력이다. 확대를 열기 전에는 입력을 전달하지 않는다.
- 클릭하지 않은 렌즈 진입은 실제 커서를 원본으로 옮기지 않는다. Down에서만 중계하고, 정상 Up 뒤 실제 커서를 렌즈 위치로 복원한다. 조작 요청은 유지한다. 누름 중 노란 가상 포인터와 실제 커서가 갈라지는 문제는 미해결 차단이며, 정상 UX로 승인된 것으로 취급하지 않는다.
- 실제 대상 누름·물리 해제 대기 중이면 영역·배율·창 배치를 잠근다. 대상 누름이 없으면 손잡이·배율을 사용할 수 있고, 조절 중 잠시 멈췄다가 버튼 해제·최신 화면 확인 뒤 자동 재개한다.
- 아래 앱에 전달되지 않은 창 손잡이 누름은 중계 해제 대기를 만들지 않는다. 실제 대상 누름은 조절 요청이 와도 Up과 물리 해제 대기를 유지한다.
- 콘텐츠 경계에서 마지막 유효 원본 위치에 Up을 보낸 뒤 잠시 멈춘다. 버튼을 놓기 전 재개하지 않는다. 버튼 해제 뒤 새 조작을 받을 준비만 하며, 추가 Down을 만들지 않는다.
- 원래 화면은 입력 해제 → 조작 요청 끄기 → 두 창 숨김 → 진입 버튼 복원 순서다. 이후 사용자가 확대를 다시 열면 새로운 조작 요청을 만든다. 배치 저장에는 입력 허용을 기록하지 않는다.
- `조작 중지`·Esc·복귀·닫기·대상 capture 손실·입력/해제 실패는 자동 재개하지 않는다. 화면 갱신 지연·캡처 실패는 버튼을 해제하고, 화면 복구 뒤 기존 요청만 재개한다.
- 배율은 실제 표시 배율을 안내한다. 화면에 맞춰 제한한 경우 요청 배율과 맞춤 결과를 구분한다.
- 일반·컴팩트의 `−/+` 배율 버튼은 0.1×씩 조절하고, 숫자 입력은 Enter 또는 포커스 이탈 때 0.25~8 범위로 정규화해 같은 안전한 배율 변경 경로를 사용한다.
- A/B 지정·카운트다운·직선 실행은 접힌 보조 도구에 두고 직접 조작과 상호 배제한다. A/B 선택 클릭은 표식만 만든다. 열기 전 직접 조작이 요청된 상태였다면 보조 도구를 닫은 뒤 재개하며, 도중 명시적 중지·복귀는 그 재개도 취소한다.
- A/B 표식과 직선 계획은 정규화 좌표를 사용한다. 직접 조작 중 가상 포인터는 A/B 표식과 구분한다.
- 현재 배율·카운트다운 버튼은 단발 클릭이다. 길게 누름 반복·우클릭·휠 등 보조 UX의 확장은 핵심 검증 뒤 진행한다.
- 입력 실패·해제 대기·보기 상태를 구분하고, API 수락을 실제 대상 반응으로 안내하지 않는다.
- 앞선 아래쪽 배치·제목부 이동·조작 유지·클릭/드래그는 사용자 확인을 받았다. 이후 지적된 드래그 중 이중 포인터는 `BLOCKED`이며 클릭 전·Up 후는 부분 수정했다. [최신 기록](../notes/runs/2026-09-10-cursor-position-diagnostic.md)의 차단·미검증 범위를 유지한다.
